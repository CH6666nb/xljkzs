## 一、你需要改的两个地址

1. `vite.config.js` 顶部的 `BACKEND_URL` —— 后端服务地址，默认 `http://localhost:8080`
2. `src/config/index.js` 的 `fileBaseUrl` —— 文件（图片）访问地址，也填后端地址，两个保持一致

改完这两个，前端就能找到你的后端了。

## 三、写后端时需要注意的点

1. **分页参数名不统一**（文档如此，前端已按文档传）：
   - 文章列表：`currentPage` / `size`
   - 管理端会话列表：`currentPage` / `size`
   - 用户端会话列表：`pageNum` / `pageSize`
   - 情绪日记管理端：`current` / `size`

   写后端时如果嫌麻烦，可以每个方法多收几个别名参数（比如 `@RequestParam(required=false) Integer current` 和 `pageNum` 都收，取非空的那个）。

2. **分页返回结构**：列表接口请统一返回 `{ records: [...], total: 总数 }`，前端表格分页组件直接用这两个字段。

3. **文章状态取值**：`0 草稿 / 1 已发布 / 2 已下线`。用户端文章列表只展示"已发布"。

4. **流式对话**返回 `text/event-stream`：每个分片一行，格式为 `data: 内容`，结束后可发 `data: [DONE]`。内容可以是纯文本分片，也可以是 JSON（前端兼容 `{"content":"..."}` 与 `{"data":"..."}`）。
   - Spring Boot 可用 `SseEmitter` 或 WebFlux 的 `Flux<ServerSentEvent>`
   - **记得关掉响应缓冲**，否则内容会攒到最后一次性发出，没有打字机效果

5. **登录返回结构**：`data` 中应包含 `token` 与 `userInfo`（含 `userType`：1 普通用户 → 跳转 `/user`，2 管理员 → 跳转 `/back`）。

6. **文件上传**返回结构：前端使用 `data.filePath` 拼接图片地址（`fileBaseUrl` + filePath）。返回相对路径即可，例：`/upload/2026/09/xxx.png`。

7. **消息角色字段**：前端兼容 `role: 'user'/'assistant'`（大小写均可）。数据库里对应 `consultation_message.role`。

8. **情绪分析**（`/session/{sessionId}/emotion`）返回结构前端优先读取：`dominantEmotion / moodScore / positiveRatio / negativeRatio / neutralRatio / summary`，其余字段会以 JSON 形式展示。

9. **时间格式**：列表类接口建议返回 `yyyy-MM-dd HH:mm:ss` 字符串（前端直接显示）。注意 `/session/start` 接口文档要求返回**毫秒时间戳**，而数据库存的是 DATETIME，需要后端转换。

10. **情绪日记唯一约束**：数据库 `emotion_diary` 表有 `(user_id, diary_date)` 唯一索引，同一天只能一条。保存接口要用"先查后改"或 `ON DUPLICATE KEY UPDATE`，不要直接 insert，否则会报唯一键冲突。

11. **密码**：数据库里的测试密码是明文 `123456`，仅方便联调。正式写登录逻辑时建议改 BCrypt 加密（`BCryptPasswordEncoder`）。
